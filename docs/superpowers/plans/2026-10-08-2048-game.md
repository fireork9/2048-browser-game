# 2048 Browser Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a standalone, responsive 2048 browser game that opens from `src/2048.html` and follows the approved specification.

**Architecture:** Keep the game model and browser controller in `src/2048.js`, the semantic page structure in `src/2048.html`, and all presentation in `src/2048.css`. The model exposes a small deterministic API that accepts an injectable random-number function, allowing the board rules to be tested with Node's built-in test runner without adding dependencies; the same file runs directly in the browser as a classic script.

**Tech Stack:** HTML, CSS, vanilla JavaScript, Node.js built-in `node:test` and `node:vm` for logic tests; no external libraries, server, or build step.

**Spec:** `src/tz_2048.md`

## Global Constraints

- The board is 4×4 and a new game starts with exactly two `2` tiles and score `0`.
- A successful move adds exactly one tile to an empty cell; a no-op move adds no tile and no score.
- Spawn selection uses a uniform integer from 0 through 99: 0–9 produces `4`; 10–99 produces `2`.
- A tile created by a merge cannot merge again during that move; score increases by the value of each merged tile.
- Controls are keyboard arrows, a touch swipe with a 30 CSS-pixel minimum, and on-screen direction buttons, all calling one move path.
- The first creation of `2048` shows a victory choice; continuing does not show victory again. No legal moves show the loss state.
- Opening `src/2048.html` must work directly in a modern browser without a server, external dependencies, or a build tool.
- Use the exact palette, dimensions, labels, modal behavior, and responsive rules in `src/tz_2048.md`.
- Do not add accounts, persistence, records, sounds, undo, extra modes, or network requests.

## Review Focus

- A full board can still have legal equal neighbors; check for merges before declaring game over. **Test:** construct a full board with a matching horizontal pair and assert `hasMoves` is true; construct a full board with no matching neighbors and assert it is false (Task 1).
- Equal tiles separated by empty cells must merge after compaction, but a newly merged tile cannot merge a second time. **Test:** verify `[2, null, 2, null]` left becomes `[4, null, null, null]`, and `[2, 2, 4, null]` left becomes `[4, 4, null, null]` (Task 1).
- A no-op move must not consume randomness, add a tile, or change score. **Test:** pass a counting random stub to a blocked move and assert board, score, and call count are unchanged (Task 1).
- A key or swipe during a modal must not mutate the board; rapid ordinary inputs must remain ordered. **Test:** test the shared move-eligibility guard and verify two successive direction inputs produce two successive state transitions; confirm the modal guard in the browser (Task 3).
- A short or diagonal swipe must honor the 30-pixel threshold and tie rule without scrolling the page. **Test:** verify 29 pixels returns no direction, 30 pixels selects one, equal-axis diagonals choose horizontal, and handled touch gestures prevent browser scrolling in the browser (Task 3).

### Task 1: Implement and test the game rules

**Files:**
- Create: `src/2048.js`
- Create: `tests/2048.test.js`

**Interfaces:**
- `window.Game2048.createInitialState(random = Math.random)` returns `{ board, score, status, hasWon }`. `board` is a 4×4 array of numbers or `null`; `score` is `0`; `status` is `'playing'`; `hasWon` is `false`. It chooses each starting position uniformly from the remaining empty-cell list, so the positions differ.
- `window.Game2048.makeMove(state, direction, random = Math.random)` accepts `direction` in `'up' | 'down' | 'left' | 'right'` and returns a new state without mutating the input. It compacts each row/column toward the requested edge, merges equal adjacent values once per tile, adds merged values to score, spawns only after a changed board, and sets `status` to `'victory'` on the first `2048` tile or `'game-over'` when no legal moves remain. On a successful move, it calls `random()` first to choose an empty position and then to choose the value; a no-op calls it zero times.
- `window.Game2048.continueAfterVictory(state)` changes a victory state to `'playing'`, preserves the board, score, and `hasWon: true`, then sets `'game-over'` immediately if no moves remain.
- `window.Game2048.hasMoves(board)` returns `true` when at least one cell is empty or at least one horizontal/vertical neighbor pair has equal values; otherwise it returns `false`.
- `window.Game2048.getSwipeDirection(startX, startY, endX, endY)` returns `'up' | 'down' | 'left' | 'right' | null` using the 30-pixel threshold and horizontal tie rule from the spec.
- `window.Game2048.getKeyboardDirection(key)` maps the four `Arrow*` key names to directions and returns `null` for every other key.
- `window.Game2048.canAcceptMove(state, modalOpen)` returns `true` only when `state.status === 'playing'` and no modal is open; the controller uses this shared guard before every direction input.
- `window.Game2048` is attached by a browser-safe IIFE, so Node tests can evaluate the same source in `node:vm` without a package manifest or third-party dependency.
